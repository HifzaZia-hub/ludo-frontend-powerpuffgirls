# 06 — Changes for D3 v1.2

D3 v1.1 was written before the backend team's Ludo Game Server (LGS) existed and before we built the
front end. `00-requirements.md` §5 asks for the differences to be written into D3 v1.2, so the
documents agree with what was built. This is that list. Each entry gives what v1.1 says, what is
true now, and where that was decided.

**Decided** means it is settled in the contract or the code. **To confirm** means it still waits on
the client (teacher or TA). Until then, the front end does what this file says. Since 2026-11-21 the
backend team builds the LGS to our contract, so nothing waits on them any more.

## 1. Architecture

| Topic | D3 v1.1 | Now | Status | Source |
|---|---|---|---|---|
| Networking | §1.1 leaves out remote multiplayer, and §3.2 says client-server isn't needed | The front end talks to the LGS over Socket.IO and REST. Our `LgsAdapter` is one implementation of the `GameAdapter` interface, which §3.2 allows | Decided | `00-requirements.md` §5, `01-contract.md` |
| Who writes the contract | — | We do. Since 2026-11-21 the backend team builds the LGS to `01-contract.md`, with our mock server as its working example | Decided | `01-contract.md` (header, §8) |
| Same-device play (FR-03) | Friends on one device | Dropped: the client said on 2026-11-21 it isn't needed. Each player uses their own browser | Decided | `00-requirements.md` §5 |
| Rooms and join codes | Not in D2 | A host creates a room. Others join with a 6-character code. A waiting room lists the seats | Decided, add to v1.2 | `01-contract.md` §1–§2 |
| Who runs the computer players | The front end passes the state to the game AI | The server runs them itself. The front end shows "Computer is thinking…" and draws the result. §3.3 allows this ("or the agreed orchestration layer") | Decided | `00-requirements.md` §5 |
| Computer "thinking" signal | — | No event for it, so the front end shows it while a computer is the active player | Decided | `01-contract.md` §8 |

## 2. Game rules: the answers to D3 §6.3's open decisions

The rules summary in the app is built from the rules the server sends (`snapshot.rules`), so it
always matches what the server does.

| Topic | D3 v1.1 | Now | Status | Source |
|---|---|---|---|---|
| First player | R2: player 1 starts | The server picks at random (G-2). The front end shows whoever the server names. The mock still always starts with seat 1 | Decided | `01-contract.md` §8 |
| Extra turns | R5: only on a 6 | On a 6, on a capture and on getting a piece home. Each can be switched off in the rules (`bonusOnSix`, `bonusOnCapture`, `bonusOnFinish`, all on by default) | Decided | `01-contract.md` §5 |
| Three 6s in a row | — | Ends the turn (`threeSixesForfeit`, on by default) | Decided | `01-contract.md` §5 |
| Safe squares | Open | 8 by default (`safeSquares`: 0, 8, 13, 21, 26, 34, 39, 47), marked with a star | Decided | `01-contract.md` §5 |
| Turn timer | — | 30 seconds by default (10–120, or 0 for no limit). Each time it runs out, the computer plays that turn and the player sees "Still there?" | Decided | `01-contract.md` §4–§5, P11 |
| No-move message | Open | "Sam can't move. Turn skipped.", with a banner "No move possible — turn skipped" | Decided | `src/feedback/copy.ts` |
| Choosing a colour (FR-06, FR-SYS-01) | Each seat picks a colour | The host picks any colour, and the room's other colours go clockwise from it. A friend joining picks from the colours still free | Decided with the client, 2026-11-21 | `01-contract.md` §1 |
| 2-player colours | — | The host's colour and the opposite corner: Red and Yellow if the host picks none (G-1) | Decided | `01-contract.md` §1 |
| 3-player colours | — | The host's colour and the next two clockwise | Decided with the client, 2026-11-21 | `01-contract.md` §1 |
| Final ranking | R11, FR-28: not produced | The server sends a ranking at the end. The win screen shows it only if it is sent | Decided | `00-requirements.md` §5 |
| Session score | Open | Wins this session, counted on the client from the server's results and kept in memory | Decided | FR-SYS-06, P10 |
| Computer difficulty | Open | Easy and Normal | Decided by the backend team, still to confirm with their Project Owner | `01-contract.md` §8 |

## 4. Added by the front end, beyond v1.1

- **Surviving problems (NFR-SYS-03, NFR-SYS-04):**
  - a refresh rejoins the same game;
  - a lost connection shows "Reconnecting…" and keeps the board;
  - a second tab gets "This game is open in another tab.";
  - every screen has an error screen with Try again.
- **Dice check (D2, for Hamza):** after a game, "Check the dice were fair" compares the server's
  locked code (`seedHash`, the SHA-256 of the seed) with the secret it reveals at the end
  (`01-contract.md` §5). If they don't agree, it says it couldn't check, never "unfair".
- **Message log and banners (FR-SYS-05):** every event in plain words, in order.
- **Keyboard play (NFR-SYS-08):**
  - R rolls, 1–4 picks a piece, Enter moves, Esc cancels, ? opens the rules and S skips an
    animation;
  - every control is reachable with Tab.
- **Browsers tested (D3 §6.3):** Chrome 157, Edge 157 and Firefox 160, on Windows
  (`evidence/NFR-SYS-09-browsers.md`).
